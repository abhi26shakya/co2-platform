## Execution plan

**Objective**: close I2 and I3 from `AUDIT_REPORT.md` — no container runs
as root, and CI catches known-vulnerable dependencies before merge.

**Deliverables**:
1. `backend/Dockerfile`: add a non-root user (mirror `frontend/Dockerfile`'s
   pattern — `addgroup`/`adduser`, `USER <name>` before `CMD`), verify the
   app still starts and can read/write whatever paths it needs (uploads
   dir, if any local storage is used) as that user.
2. `ml-service/Dockerfile`: same treatment.
3. `.github/workflows/ci.yml`: add a `pip-audit` step to the `backend` and
   `ml-service` jobs (after `pip install`), and an `npm audit --audit-level=high`
   (or similar) step to the `frontend` job. Decide up front whether audit
   failures should fail the build or just report — recommend failing on
   high/critical only, to avoid noisy false-start friction.
4. Add `.github/dependabot.yml` covering all three ecosystems (`pip` ×2 for
   backend/ml-service, `npm` for frontend, `github-actions` for the
   workflow file itself).

**Acceptance criteria**:
- `docker build` succeeds for all three services; containers run as a
  non-root user (`docker run --rm <image> whoami` ≠ `root`).
- CI's three jobs still pass end-to-end with the new audit steps added.
- A deliberately-outdated/vulnerable dependency (test locally, don't
  commit) causes the relevant audit step to fail, confirming it's wired
  correctly — then revert the test change.
- `dependabot.yml` validates (GitHub's own schema check on push).

**Dependencies**: none blocking — can start immediately.

**Implementation order**: Dockerfiles first (independent, low-risk,
directly closes I2), then CI audit steps (verify locally with
`pip-audit`/`npm audit` before adding to the workflow), then Dependabot
config last (purely additive, no build-time risk).

**Testing requirements**: local `docker build` + `docker run` smoke test
per service; push to a branch and confirm the CI workflow runs clean
before merging to `main`.

**Documentation updates**: mark I2/I3 resolved in `AUDIT_REPORT.md`'s
findings table once shipped; note the change in `CHANGELOG.md` and add a
new milestone entry in `PROJECT_PROGRESS.md`.

**Estimated complexity**: Small-Medium (a few hours — mechanical Dockerfile
changes, CI config, no application logic touched).

**Potential risks**: a non-root user lacking filesystem permissions the
app needs at runtime (e.g. local upload storage, if backend writes to a
path owned by root) — verify with a real container run before merging,
not just a build.

**Completion checklist**:
- [ ] `backend/Dockerfile` non-root user
- [ ] `ml-service/Dockerfile` non-root user
- [ ] CI `pip-audit` steps (backend, ml-service)
- [ ] CI `npm audit` step (frontend)
- [ ] `.github/dependabot.yml`
- [ ] `AUDIT_REPORT.md` I2/I3 marked resolved
