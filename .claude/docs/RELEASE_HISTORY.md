# Release Management Principles

The project follows these principles:

- Maintain clear release history.
- Document major changes.
- Preserve historical context.
- Link releases with documentation.
- Track project evolution.

---

# Maintenance Guidelines

Update this document whenever:

- A major release occurs.
- A significant milestone is achieved.
- Architecture evolves.
- Major infrastructure changes happen.
- Product direction changes.

Do not update for:

- Small bug fixes.
- Minor code changes.
- Individual commits.

This document should remain the high-level historical record of the project's evolution.
