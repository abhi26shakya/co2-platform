## Session 3

**Focus**: KI-010 fix (Settings preference race condition).

- Decide the approach up front: shared mutation/queue that merges against
  the latest React Query cache at send time, vs. switching
  `PUT /settings/preferences` to real PATCH semantics. The PATCH route is
  probably the more durable fix (removes the whole class of full-replace
  race conditions, not just this one instance) but touches the backend
  schema/endpoint — size it before committing to a session.
- Add a regression test that reproduces the race (two near-simultaneous
  preference writes) and asserts both fields survive.

Estimated: half to a full session depending on which approach is chosen.
