# Sprint Command

## Purpose

Plan and execute a complete Agile sprint.

Convert roadmap priorities into actionable work while maintaining quality, collaboration, and predictable delivery.

The sprint should produce measurable progress toward project goals.

---

# Objectives

Answer the following questions:

- What work should be completed this sprint?
- Why is each task included?
- What are the sprint goals?
- Who owns each task?
- What dependencies exist?
- What risks may block progress?
- How will success be measured?

---

# General Rules

Always:

- Prioritize high-value work.
- Respect roadmap priorities.
- Keep sprint scope realistic.
- Deliver working software.
- Track progress continuously.
- Document sprint outcomes.

Never:

- Overcommit work.
- Ignore technical debt.
- Add scope without justification.
- Leave blockers undocumented.

# Phase 1 – Sprint Goal

Startup Product Manager should define:

- business objective
- user value
- measurable outcome
- sprint success criteria

Sprint goals should be clear and measurable.

---

# Phase 2 – Backlog Refinement

Project Manager should review:

- feature requests
- bugs
- technical debt
- infrastructure work
- documentation tasks
- research work

Remove duplicate or obsolete items.

---

# Phase 3 – Prioritization

Prioritize work using:

- business value
- engineering effort
- technical risk
- dependencies
- customer impact

Recommend MoSCoW or RICE prioritization.

---

# Phase 4 – Sprint Planning

Create sprint backlog.

Each item should include:

- title
- description
- priority
- owner
- dependencies
- estimated effort
- acceptance criteria

---

# Phase 5 – Architecture Review

Software Architect should identify:

- required architectural changes
- reusable components
- design constraints
- scalability considerations

---

# Phase 6 – Engineering Allocation

Assign work to:

Backend Engineer

Frontend Engineer

Database Engineer

API Engineer

Data Engineer

ML Engineer

Climate AI Engineer

Satellite Imagery Engineer

DevOps Engineer

Ensure responsibilities are clearly defined.

---

# Phase 7 – Quality Planning

QA Engineer should prepare:

- testing strategy
- regression plan
- acceptance validation
- automation requirements

---

# Phase 8 – Security & Performance Planning

Security Engineer should identify:

- security-sensitive work
- required reviews

Performance Engineer should identify:

- optimization opportunities
- benchmark requirements

# Phase 9 – Risk Management

Identify:

- technical risks
- dependency risks
- resource risks
- schedule risks
- infrastructure risks

Assign:

Likelihood

Impact

Mitigation

Owner

---

# Phase 10 – Daily Execution Tracking

Track:

- completed work
- in-progress work
- blocked work
- emerging risks
- scope changes

Keep sprint status current.

---

# Phase 11 – Sprint Review

Evaluate:

- completed goals
- unfinished work
- acceptance criteria
- customer value delivered

Document demo-ready outcomes.

# Phase 12 – Sprint Retrospective

What went well

What went poorly

What should change

Action items

Lessons learned

Promote continuous improvement.
