# Documentation Checklist

## Purpose

This checklist verifies that all project documentation is accurate, complete, and synchronized with the current implementation.

Documentation should enable developers, contributors, and users to understand, use, maintain, and extend the project without relying on tribal knowledge.

Complete every applicable item before considering documentation complete.

---

# 1. General Documentation

- [ ] Documentation reflects the current implementation.
- [ ] Information is technically accurate.
- [ ] Outdated content removed or updated.
- [ ] Terminology is consistent throughout the project.
- [ ] Formatting follows project standards.
- [ ] Internal links are valid.

---

# 2. README

- [ ] Project description updated.
- [ ] Features list updated.
- [ ] Installation instructions verified.
- [ ] Quick start guide tested.
- [ ] Usage examples updated.
- [ ] Requirements documented.
- [ ] License information verified.
- [ ] Contribution guide updated if required.

---

# 3. Architecture Documentation

- [ ] System architecture documented.
- [ ] Component responsibilities explained.
- [ ] Data flow documented.
- [ ] API architecture documented.
- [ ] Database architecture documented.
- [ ] Architecture diagrams updated if required.

---

# 4. API Documentation

If applicable.

- [ ] Endpoints documented.
- [ ] Request parameters documented.
- [ ] Response formats documented.
- [ ] Authentication documented.
- [ ] Error responses documented.
- [ ] Example requests provided.
- [ ] Example responses provided.
- [ ] Version information updated.

---

# 5. Database Documentation

If applicable.

- [ ] Schema documented.
- [ ] Relationships documented.
- [ ] Migrations documented.
- [ ] Constraints documented.
- [ ] Indexes documented.
- [ ] Backup and recovery documented if required.

---

# 6. Deployment Documentation

- [ ] Deployment process updated.
- [ ] Environment variables documented.
- [ ] Infrastructure changes documented.
- [ ] Rollback procedure documented.
- [ ] Monitoring requirements documented.
- [ ] Health check procedures documented.

---

# 7. User Documentation

If applicable.

- [ ] User workflows documented.
- [ ] Configuration instructions updated.
- [ ] Screenshots updated if necessary.
- [ ] Examples verified.
- [ ] Known limitations documented.
- [ ] Frequently asked questions updated if applicable.

---

# 8. Developer Documentation

- [ ] Repository structure documented.
- [ ] Development setup verified.
- [ ] Build instructions verified.
- [ ] Testing instructions updated.
- [ ] Coding standards referenced.
- [ ] Contribution workflow documented.

---

# 9. Code Documentation

- [ ] Public APIs documented.
- [ ] Complex logic explained where necessary.
- [ ] Comments describe intent rather than implementation.
- [ ] Obsolete comments removed.
- [ ] Generated documentation refreshed if applicable.

---

# 10. Release Documentation

- [ ] Changelog updated.
- [ ] Release notes prepared.
- [ ] Breaking changes documented.
- [ ] Migration instructions documented if required.
- [ ] Version information updated.

---

# 11. Cross-Reference Verification

- [ ] Documentation links are valid.
- [ ] Related documents reference each other correctly.
- [ ] Specifications reference implementation where appropriate.
- [ ] Architecture documents align with current design.
- [ ] Memory files updated if applicable.

---

# 12. Final Review

Before approval:

- [ ] Documentation reviewed for accuracy.
- [ ] Grammar and spelling checked.
- [ ] Examples verified against current implementation.
- [ ] No placeholder text remains.
- [ ] No outdated screenshots or diagrams remain.
- [ ] Documentation is ready for publication.

---

# Documentation Completion Criteria

Documentation is considered complete only when:

- It accurately reflects the implementation.
- Setup instructions work from a clean environment.
- API documentation matches the code.
- Architecture documentation reflects the current system.
- User and developer guides are up to date.
- Release documentation is complete.
- All documentation has been reviewed for clarity and correctness.
